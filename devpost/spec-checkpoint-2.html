Historical checkpoint 1 · not recommended as production transport

WebContentsView + unrestricted browser-level CDP

The baseline demonstrated same-target control but exposed context-cookie mismatch and blanket input-veto failures. Its random loopback port did not authenticate or confine browser-wide debugging access.

The failed observations remain in checkpoint-1-results.json. Checkpoint 2 changes the attachment variant; it does not pretend the original listener became secure by placing a proxy in front of it.

Documented comparator · not runtime-probed

WebContentsView + experimental Electron automation

Playwright's Electron launcher is officially experimental and has main-process inspection/nodeCliInspect implications. It needs an explicit launch/supervision, packaging, and hardening design, plus the same guest partition and handoff tests.

Its implementation uses Chromium and Node debugging endpoints; it is not automatically a higher-fidelity Playwright-protocol replacement. The version-specific guest behavior remains unvalidated here.

Recommended provisional continuation · bounded lab tested

Native guest debugger + scoped authenticated CDP

Playwright connectOverCDP talks to a guest-scoped WebSocket bridge backed by the exact displayed WebContents' native debugger. Native partition-bound cookie APIs, per-generation revocation and trusted native shielding address the baseline cases.

  • 401 for missing credentials, browser-Origin clients and malformed multibyte tokens with the host responsive; 409 for a second authorized client; invalid controller bootstrap and workspace attachment denied.
  • The requested unrestricted Chrome debug port is closed. This is a scoped attachment variant, not an open browser listener hidden behind a proxy.
  • Custom protocol maintenance is a real cost. OOPIF/workers, broader APIs, DevTools detachment and production policy/lifecycle still block final selection.
Why the older or ordinary alternatives are not the default

BrowserView is deprecated and replaced by WebContentsView; it does not solve control ownership or attachment fidelity. Ordinarily launched standalone Chromium and screenshot transport do not meet the approved native embedded exact-session experience. Any proposed product change requires discussion and approval.

What was corrected, rather than hidden
  • Initial OS-input offsets were traced through DOM pointer coordinates to double DPI scaling in PowerShell. Per-monitor-v2 coordinates fixed the harness. Obscured windows, moved pointers and held modifiers cause an honest INCONCLUSIVE result, never injected input into another app.
  • A desktop run exposed later actionability stalls. Three background-scheduling switches from pinned Playwright were added without its security-disabling switches; both current hidden-window observable-effect tests passed.
  • Direct review caught unknown-result handoff releasing User control. The captured failing contract run and current native case show the regression and correction. Unknown results remain unknown and excluded from competing control.
  • A malformed multibyte authorization token exposed a character-length versus byte-length mismatch before timingSafeEqual. The RED selected-case run records the rejection timeout; a byte-length check fixes it. The GREEN regression and both current full runs observe 401 and a responsive host.
  • The independent-review tool was unavailable; direct self-review and executable checks were completed. npm audit recorded zero known advisories at this snapshot, with maintenance/deprecation limitations retained.

Follow one audit through the proposal.

Validate current setup.

The trusted setup UI sends validated configuration to preflight. Keys remain in the credential boundary; fresh consent, valid budgets, provider/target checks, and one-active-audit gating precede activation.

Bind one actual native target.

The host creates the isolated audit guest and proves target identity. The Agent receives a scoped automation facade only after ownership and boundary gates pass.

Record effects, then reconcile control.

Actions produce observed effects, not inferred success from a tool promise. Current CDP and bounded handoff/recovery cases have passing evidence; safety-aborted native checks stay inconclusive. Current-artifact input reruns, human input and generic Agent/TODO/history reconciliation remain mandatory work.

Resolve structured questions safely.

UI and trusted runtime validate answers and explicitly supported Skip. One-operation approval stays distinct. Ordinary question answers cannot reclaim a User-owned browser.

Recover without replay.

Provider retry does not repeat browser actions. Renderer replacement invalidates old handles and rebinds the native view; User and Handoff-Pending restoration follow the approved explicit-control policy. Full scheduling/race behavior still needs proof.

Verify actual evidence.

Require traceable expectations, real Agent execution, independent reproduction, and false-positive checks. Incremental records preserve trustworthy partial results; termination never replays uncertain operations.

Open read-only local history.

Completed/Blocked/Interrupted reports and compact chronological entries remain local, classification-accurate, privacy-protected, and independent of another active audit. Opening history never resumes execution.

What still blocks final selection.

Human input and full protocol fidelity

Human hardware/IME, accessibility/UI Automation, touch, drag/drop, shortcuts/modals and broader DPI/focus coverage are not validated. The scoped protocol subset still needs OOPIF/worker/service-worker, complete storage/permission/download and cleanup proof.

Production effect-policy binding

The tested grant is one fixed method/path/generation request from a trusted diagnostic catalog. Arbitrary target semantics, contract provenance, payload/resource/recipient binding and background-request races are not solved. Do not ship that fixture permit map as the full PRD policy.

Whole-product lifecycle and release

Complete automatic uncertainty recovery, Agent/TODO/durable history reconciliation, old-partition cleanup, whole-host/OS interruption, signed installer, integrity-enforcement fuse, upgrade and packaged Agent worker remain unvalidated. The native packaged host test uses an external controller.
