Browser, session and exclusive ownership

Start with Electron 45.0.0 / Playwright Core 1.64.1. Adapt the working scoped bridge, native partition adapter and coordinator. Keep sandbox/context isolation/webSecurity, no privileged guest preload, authenticated loopback guest-only CDP, per-generation revocation and explicit native cleanup.

One operation lease at a time. User/Agent never control concurrently. Unknown outcomes remain excluded and are not replayed; Return reinspects page/session and reconciles history. Fix actual focus/protocol blockers as they arise.

Autonomous runtime, questions and TODOs

One Electron utility-process worker runs AI SDK ToolLoopAgent. Offer typed browser, evidence, TODO, ask_user and finding-proposal tools; no arbitrary JavaScript, shell or filesystem tool for the model. Stream real activity, not hidden reasoning.

Main validates question membership/counts/text/formats. Invalid/dismissed answers remain pending; supported Skip stays distinct. Secrets are ephemeral references, normal accepted answers may persist, and existing audit/ownership/TODO states remain separate.

Common authorization and risk policy

Playwright and WebMCP share the same main-process policy and lease path. Enforce authorized localhost origin/scope with tool and native navigation/request guards for both owners. Understood low-risk effects run; eligible meaningful/uncertain effects require exact one-use approval; hard restrictions stay blocked.

Bind approval to audit, generation, operation, exact arguments and resources. Treat tool hints/GET methods as insufficient safety proof. Unknown unbounded effects must be skipped, not silently allowed. Disclose limits of arbitrary backend-effect inference.

Evidence, verification and saved reports

Persist action start and independently observed result, safe screenshot/DOM evidence and actual tool-event references. Omit unsafe artifacts; redact secrets and avoid raw prompts/bodies/errors in diagnostics.

Trusted validation, not model assertion, assigns Verified after expectation, evidence, safe independent Playwright reproduction and false-positive checks. Preserve Suspected/UX classifications and honest coverage. Local read-only overviews use recorded data only.

Four BYOK providers and OS-backed credentials

Direct AI SDK OpenAI, Anthropic, Gemini and OpenAI-compatible OpenRouter adapters; editable model ID and tool-capability preflight. Initial researched pins: ai 7.0.152, OpenAI 4.0.101, Anthropic 4.0.87, Google 4.0.104, compatible 3.0.77. Lock compatible remaining patches during the first slice.

Main uses asynchronous safeStorage after readiness, stores ciphertext separately, and returns configured status only. No saved plaintext or automatic provider/model switching. Live-provider checks depend on supplied keys; unavailable usage/cost stays explicit. Exact endpoints/payload/response contracts are in the canonical spec.

Thin, optional adapter

Discover once per main-frame document with a 1.5-second timeout and refresh before invocation. Available / No tools / Unavailable; absence or discovery failure means ordinary Playwright. No website integration is required.

Cap discovery at 20 tools, 2,000-character descriptions and 64KiB total metadata. Validate inputs, bound calls to 15 seconds, sanitize output and clear stale discovery on navigation/recovery.

Same rules, no UX shortcut

Page names/descriptions/schemas/hints/results are untrusted. Use shared authorization, risk policy and ownership, independently observe effects and attribute tool actions accurately.

Never skip the visible UI the goal is testing. After a tool timeout/throw, inspect the uncertain outcome before any alternative; do not redo a possibly completed operation through Playwright. If runtime compatibility breaks, defer this adapter and continue the core audit.

Small contracts. Real boundaries.

Five local tables

projects, audits, events, findings, settings. Main owns SQLite/Drizzle. Typed event/progress JSON holds evolving TODOs, questions, ownership and usage instead of separate infrastructure.

Safe artifacts live under userData/evidence with event-linked hashes. Keys are separate ciphertext; cookies/secret references stay in memory. Stable session ordering and read-only history survive restart.

One typed event stream

Validated commands use request IDs; safe events use audit ID and monotonically increasing seq. Persist before publication, deduplicate and fetch missed state on return. Validate sender/audit/generation and reject stale tool work.

Narrow preload commands cover setup/provider tests, start, question/Skip, Take/Return Control, native slot layout and saved-content queries. Worker tool requests use the same trusted main broker.

Execution limits and the failures we actually handle

Approved defaults: 40 model steps, 10-minute wall-clock budget, 15-second browser/WebMCP action timeout, 45-second model-request timeout and 5-second cleanup deadline. Waiting/User-control time counts; optional token/cost caps apply when measurable.

  • Provider interruption: preserve state, show Reconnecting, retry only the failed model request up to three times within budget; no multiplied SDK retries, tool replay or automatic provider switch.
  • Browser crash: at most two recreations, invalidate stale handles/grants, inspect actual state; restore User or Awaiting Control Decision as required. No safe recovery means Interrupted.
  • Invalid/dismissed questions remain pending. Skip/denial/restriction seeks a safe alternative; no continuation means Blocked with the actual distinct reason.
  • Shutdown, worker/storage failure or budget exhaustion: exclude new work, bounded in-flight handling, Unknown when unestablished, preserve partial Interrupted records and discard temporary secrets. Next launch never auto-runs incomplete history.

Six slices. Working software at each step.

01 / LAUNCHABLE SHELL

See and control the real page.

Electron, typed preload, premium workspace and actual native Playwright interaction. Package the shell and bundled worker early to expose real distribution blockers.

02 / LOCAL SETUP

Connect and start cleanly.

Database, encrypted keys, four provider adapters, capability preflight, non-sensitive drafts, current consent and one-active-audit guard.

03 / AUTONOMOUS RUN

Watch an agent do useful work.

Bounded SDK loop, serialized browser tools, actual feed/TODOs, validated ask_user, Take/Return Control and essential origin/risk enforcement.

04 / EVIDENCE + REPORT

Make findings trustworthy.

Safe real artifacts, conservative verification, actual terminal outcomes and saved read-only history after restart.

05 / OPTIONAL WEBMCP

Add structure without dependency.

Thin discovery/call adapter through existing gates. Verify no-tools/unsupported fallback and preserve visible UX testing. Defer optional blockers.

06 / ACCEPTANCE + DEMO

Show the complete value.

Add the sign-in fixture later, reproduce the seeded issue, check a denied/out-of-scope action and secret outputs, smoke-test Interrupted behavior and packaged launch, then record and prepare submission.

What is deliberately deferred

Broad OOPIF/worker/CDP compatibility matrices; exhaustive hardware/IME/multi-monitor/DPI input campaigns; advanced concurrency/race and long-duration performance studies; signing/updater and advanced ASAR-integrity work. Preserve basic approved recovery, secrets, budgets and permission rules. Fix actual core/security blockers during development instead of adding another broad prerequisite checkpoint.

Historical inconclusive cases remain inconclusive; the previous checkpoint and evidence index are support and limitations, not the new work queue.
